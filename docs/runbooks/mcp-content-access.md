# MCP-доступ к контенту сайта

Этот runbook описывает выпуск, подключение, проверку, ротацию и отзыв Bearer-токенов для MCP endpoint сайта. Секрет токена показывается в админке один раз. Не сохраняйте его в Git, TOML-конфигурации, тикетах или логах.

## Подготовка и развёртывание

1. Примените миграции той же версией приложения, которую разворачиваете:

   ```bash
   yarn db:migrate
   ```

2. Разверните приложение и проверьте readiness. Проверка завершится ошибкой, если миграция `mcp_tokens` не применена:

   ```bash
   curl --fail --silent https://kordev.team/api/health/ready
   ```

3. Войдите в админку и откройте `https://kordev.team/admin/mcp/`.

## Выпуск токена

Создавайте отдельный токен для каждого клиента или устройства. Укажите понятное имя, ограниченный срок действия и только необходимые права:

| Право | Возможности |
| --- | --- |
| `content:read` | `list_content`, `get_content` |
| `content:write` | `create_content_draft`; вместе с `content:read` — `update_content_draft` |
| `content:publish` | `publish_content`, `unpublish_content` |
| `media:read` | `list_media` |
| `media:write` | `upload_image` |

Для подготовки текстов обычно достаточно `content:read` и `content:write`. Право `content:publish` выдавайте только клиенту, который действительно должен публиковать материалы. Для загрузки изображений добавьте `media:write`.

После нажатия «Создать токен» сразу скопируйте секрет: повторно он не показывается. Сохраните его только в локальной переменной окружения или в менеджере секретов. Например, для текущей терминальной сессии:

```bash
read -s KORDEV_MCP_TOKEN
export KORDEV_MCP_TOKEN
```

## Подключение Codex

Добавьте в конфигурацию Codex ссылку на endpoint, но не сам секрет:

```toml
[mcp_servers.kordev_site]
url = "https://kordev.team/mcp"
bearer_token_env_var = "KORDEV_MCP_TOKEN"
```

Для локального production-mode сервера замените URL на `http://127.0.0.1:3003/mcp`. После изменения конфигурации и переменной окружения полностью перезапустите или перезагрузите Codex, чтобы он перечитал оба значения.

## Приёмочная проверка

1. Вызовите `list_content` и убедитесь, что список инструментов соответствует выданным правам.
2. Создайте одноразовый черновик через `create_content_draft`. Используйте уникальный slug с пометкой `mcp-smoke` и не передавайте право публикации, если оно не требуется для проверки.
3. Откройте материал в редакторе админки: статус должен быть `draft`, версия — `1`.
4. Получите актуальное состояние через `get_content`, затем вызовите `update_content_draft` с `expectedVersion: 1`. Повторно проверьте материал: версия должна стать `2`.
5. Если проверяется медиатека, загрузите небольшой PNG через `upload_image`, задав осмысленный `altText`, либо `decorative: true` для декоративного изображения. Откройте возвращённый `publicUrl` и убедитесь, что файл доступен.
6. Публикуйте материал через `publish_content` только после явной проверки человеком и только токеном с `content:publish`.
7. Отзовите тестовый токен на странице `/admin/mcp/` и повторите запрос: endpoint должен вернуть HTTP `401`.
8. Удалите одноразовый материал и тестовое изображение через существующий интерфейс админки. MCP намеренно не предоставляет инструментов удаления.

## Ротация

1. Выпустите новый токен с теми же или более узкими правами и коротким периодом параллельной работы.
2. Обновите значение `KORDEV_MCP_TOKEN` в менеджере секретов или окружении клиента и перезапустите клиент.
3. Проверьте `list_content` новым токеном.
4. Отзовите старый токен в `/admin/mcp/`.
5. Убедитесь, что новый токен работает, а старый получает `401`.

Не переиспользуйте один токен между несколькими людьми или устройствами: отдельные токены позволяют отозвать один доступ, не останавливая остальные.

## Инцидент и экстренный отзыв

Если секрет мог попасть в логи, переписку, историю shell или стороннюю систему:

1. Немедленно отзовите токен в `/admin/mcp/`; не ждите выпуска замены.
2. Проверьте время последнего использования и сопоставьте его с серверными audit-записями `mcp_tool` по безопасному `tokenId`.
3. Выпустите новый токен с минимальными правами, обновите клиент и проверьте подключение.
4. Проверьте созданные черновики, публикации и загруженные изображения за подозрительный период.
5. Если скомпрометирован токен с `content:publish`, отдельно проверьте опубликованные материалы и при необходимости снимите их с публикации через админку или `unpublish_content` новым доверенным токеном.

Отзыв действует на следующий запрос. Ответы авторизации не раскрывают, был ли токен просрочен, отозван или связан с неактивным администратором.
