# Recommendation reconciliation

For explicitly owner-approved exact patches, see [protected execution](approved-seo-recommendation-execution.md). Migration0024 blocks generic transitions into implemented; approval/application/public verification have separate append-only events. Old accepted status alone is not authority. Evidence reconciliation never publishes a page.

`list_seo_recommendation_history` reads one card's before/after snapshots, reasons, times and actors under seo:read. `revise_seo_recommendation` requires seo:read+seo:write and expectedUpdatedAt; it cannot change page/query/issue/fingerprint identity. Admin Changes links expose the same immutable history without writes during reads. Pre-migration changes are not reconstructed: the first new update stores the full existing before image.

Actual create, deduplicated evidence refresh, status changes and explicit revisions all append audit events transactionally. Each mutation advances updatedAt by at least1ms. Concurrent stale differing revisions fail closed. An identical-content replay is a no-op even with its original timestamp; changing only a retry reason does not manufacture another revision. New externally resolved tasks may be dismissed with a factual reason; never mark them implemented to invent work or rank improvement.

For a reviewed operational batch, resolve and verify the actual active immutable web slot as in seo-page-control.md, then pipe a JSON array into `docker exec -i kordevteam-<verified-slot> node server/seo-recommendations-reconcile.mjs`. Input is bounded to1MiB/100 unique card IDs, strict full fields and reason. All items commit together or none do. The actor is explicitly saved-audit-reconcile, not a human. Only safe revised/unchanged counts or seo_recommendation_reconcile_failed are printed. Read latest cards before constructing expectedUpdatedAt; never bypass a conflict with blind SQL. Immediate replay must return unchanged.

The decision cycle reads saved 7/14/28 checkpoints, current published page/version, assigned keys, source freshness, official index evidence and existing recommendations/history. Mature compatible adequately sampled evidence can support a proposed action with numerator/denominator, source/cohort/windows, uncertainty and a measurable minimum effect. Pending/insufficient states are not failures and do not justify changing text. Technical/index exclusions may support evidence-based recommendations without waiting for rank windows. Approval, publication, core activation, new provider calls and budgets remain separate human-controlled operations. Update a matching logical issue rather than create a second card on every changed evidence snapshot; do not infer issue identity from old heterogeneous fingerprints.
