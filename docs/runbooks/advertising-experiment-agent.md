# Агент рекламных экспериментов: база знаний

Этот runbook относится к Knowledge foundation: локальной базе исследований, гипотез, паспортов экспериментов, метрик, CRM-ссылок без контактов, выводов и audit trail. Панель `/admin/ads/` предназначена для чтения; вручную в ней можно добавить только заметку к эксперименту.

> Эта версия не умеет создавать, запускать, останавливать или менять рекламу в VK и не обращается в CRM. Идентификаторы внешних объектов и сделок здесь только фиксируют уже известные связи. Перед будущим подключением VK/CRM потребуется отдельная реализация, проверка безопасности и явное согласование.

## Подготовка

1. Примените миграции той же версией приложения, которую разворачиваете:

   ```bash
   yarn db:migrate
   ```

2. Проверьте readiness приложения и откройте `/admin/ads/`. Пустые разделы до первого эксперимента — нормальное состояние.
3. Откройте `/admin/mcp/` и убедитесь, что старые токены не получили рекламные права автоматически. Области доступа сохраняются в записи каждого токена; новую возможность надо выдать явно.

## Отдельный токен агента

Выпускайте отдельный токен только для рекламного агента, с понятным именем и ограниченным сроком. Снимите все флажки, кроме:

| Область | Возможность |
| --- | --- |
| `ads:read` | Читать источники, сигналы, гипотезы, эксперименты, выводы, журнал и экономику |
| `ads:write` | Записывать локальные исследования и результаты; работает только вместе с `ads:read` |

`ads:write` без `ads:read` не открывает ни одного инструмента. Не добавляйте права контента, публикации, медиа или SEO, если тот же клиент не выполняет отдельную задачу, для которой они действительно нужны.

Секрет показывается один раз. Храните его в менеджере секретов или в переменной окружения, но не в Git, конфигурационном файле, переписке, задаче или журнале команд. Пример безопасного ввода для текущей shell-сессии:

```bash
read -s KORDEV_ADS_MCP_TOKEN
export KORDEV_ADS_MCP_TOKEN
```

Пример конфигурации содержит только имя переменной, не секрет:

```toml
[mcp_servers.kordev_ads]
url = "https://example.invalid/mcp"
bearer_token_env_var = "KORDEV_ADS_MCP_TOKEN"
```

## Приёмочная проверка

1. Получите список инструментов. У токена с `ads:read` должны быть только десять read-инструментов рекламы. При добавленном `ads:write` появляются тринадцать команд записи.
2. Вызовите `get_ads_overview`; пустая сводка допустима.
3. Создайте один синтетический источник через `create_ad_research_source`, затем одну гипотезу-кандидата через `create_ad_hypothesis`. Для каждой команды сгенерируйте отдельный UUID `idempotencyKey` и сохраните его до получения однозначного ответа.
4. Повторите ту же команду с тем же телом и тем же ключом: результат должен совпасть, в базе не должна появиться вторая запись.
5. Откройте `/admin/ads/hypotheses/` и убедитесь, что кандидат виден. Не переводите его дальше только ради smoke-test.
6. Проверьте, что токен с одним `ads:read` не видит write-инструменты, а скрытый вызов write-команды отвергается до обращения к сервису.
7. После проверки отзовите тестовый токен, если он больше не нужен.

## Идемпотентность и восстановление

Каждая write-команда требует уникальный UUID `idempotencyKey`.

- Таймаут или потеря ответа: повторите точное имя команды и точное тело с тем же ключом.
- `ads_idempotency_in_progress`: не создавайте новый ключ немедленно; дождитесь завершения текущей обработки и повторите исходную команду.
- `ads_idempotency_conflict`: ключ уже связан с другой командой или другим телом. Не подбирайте новое тело под старый ключ; сначала прочитайте актуальное состояние и разберите журнал.
- `ads_hypothesis_conflict`, `ads_experiment_conflict`, `ads_learning_conflict`: передайте свежую `version` только после повторного чтения объекта.
- `ads_*_transition_invalid` или `ads_verdict_invalid`: исправьте порядок жизненного цикла или доказательства, не обходите правило новой произвольной записью.
- `ads_validation_error`: удалите неизвестные поля, контакты и секреты, проверьте UUID, ISO-даты, суммы и ограничения размера.
- `ads_unavailable`: безопасная общая ошибка. Проверьте readiness, PostgreSQL и серверный audit по `tokenId`; ответ намеренно не раскрывает внутреннюю причину.

Команда с окончательно неясным результатом не должна автоматически переходить к следующей стадии. Сначала прочитайте сущность и журнал, затем решите, повторять ли исходный ключ.

## Ротация и отзыв

1. Выпустите новый токен только с `ads:read`/`ads:write` и коротким периодом параллельной работы.
2. Обновите `KORDEV_ADS_MCP_TOKEN` в менеджере секретов, перезапустите MCP-клиент и проверьте `get_ads_overview`.
3. Отзовите старый токен на `/admin/mcp/`.
4. Убедитесь, что новый токен работает, а старый получает единый ответ авторизации `401`.
5. При возможной утечке сначала отзовите токен, затем изучите audit-записи `mcp_tool` по безопасному `tokenId` и журнал `/admin/ads/events/`.

Не переиспользуйте один секрет между людьми, устройствами и автоматизациями. Отдельный токен даёт точного автора MCP-команд и позволяет локально отозвать доступ.

## Резервное копирование и восстановление

Рекламная память хранится в PostgreSQL вместе с основными данными приложения и должна попадать в штатную резервную копию. Критичны таблицы `ad_research_sources`, `ad_market_signals`, `ad_hypotheses`, `ad_experiments`, `ad_experiment_variants`, `ad_metric_snapshots`, `ad_lead_attributions`, `ad_experiment_events`, `ad_learnings` и `ad_command_receipts`.

После восстановления проверьте миграции, количество гипотез/экспериментов, последние события и command receipts. Не очищайте receipts отдельно от предметных записей: они нужны для безопасного повтора команд после сбоя. Восстановление копии не инициирует внешние действия, потому что в этом релизе нет клиентов VK/CRM и фоновых планировщиков рекламы.

## Граница данных

- Допустимы внутренние UUID, безопасные ID объектов рекламной системы и CRM, агрегированные метрики и суммы.
- Нельзя передавать имя лида, телефон, email, файлы, cookies, access tokens, client secrets, заголовки авторизации и сырые ответы поставщиков.
- Фактическая выручка и потенциальная сумма показываются отдельно. Потенциальная сумма не считается полученной выручкой.
- Вердикт без размера выборки и ограничений запрещён; маленькая выборка должна быть явно видна рядом с выводом.
- Панель не является интерфейсом управления ставками, бюджетом или статусом внешней рекламной кампании.
